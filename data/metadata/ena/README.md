# Draft FASTQ/ENA Metadata Overview

These files are draft metadata aids for ENA submission. They were generated by
`scripts/12_ena_fastq_overview.py` from historical metadata in `../old/`.

## Main output

- `fastq_ena_overview_draft.csv`: one row per curated Snowy Owl sample. This is
  the main working table for ENA preparation.
- `fastq_ena_overview_curated.csv`: manually curated copy of the draft table.
  Edit this file, not the generated draft, so script reruns do not overwrite
  manual checks.

Important columns to manually curate before submission:

- `fastq_r1_file`, `fastq_r2_file`: actual FASTQ filenames.
- `trimmed_pair_r1_files`, `trimmed_pair_r2_files`: trimmed paired FASTQ files
  recovered from the cluster listing. These are useful for reconstructing
  sample provenance but should not be treated as final ENA raw-read filenames.
- `ena_run_accession`, `ena_experiment_accession`: fill after ENA submission or
  when preparing the ENA template.
- `instrument_model_or_run`: not resolved per sample from the recovered files.
- `sequencing_centre_or_provider_inferred`: inferred only where the source file
  makes this clear enough; verify.
- `submitted_material_or_library_type`, `submission_comments`: useful evidence
  for library prep, but exact kit/protocol should be checked against lab records.
- `manual_check_flags`: compact list of unresolved issues for each sample.

## Supporting outputs

- `sequencing_lane_stats_clean.csv`: cleaned rows from
  `../old/lab_seq/snowy-owls_lanestats.xlsx`. These map to the DAG-BS/New York
  batch and include OMRF names, indexes, Q30, read counts, and yield.
- `sample_submission_rows_clean.csv`: cleaned and matched rows from the NSC
  sample-submission tables. This recovers old sample codes, submitted material
  or library type, requested output, and comments.
- `historical_alignment_qc_from_old_supplement.csv`: extracted table from
  `../old/supporting_info/Supplementary data.docx`, including GC, insert size,
  coverage, and percent aligned.
- `trimmed_fastq_files_clean.csv`: one row per trimmed FASTQ file parsed from
  `trimmed_fastq_filenames.txt`.
- `trimmed_fastq_by_match_code.csv`: trimmed FASTQ evidence collapsed by
  inferred sample code, such as `X11`, `WRG1`, or `DAG-BS-1`.
- `trimmed_fastq_filenames.txt`: pasted cluster file listing used as the source
  for trimmed FASTQ parsing.

## Current trimmed FASTQ reconstruction

- All 68 curated Snowy Owl samples have at least one matching trimmed paired
  FASTQ set in the pasted cluster listing.
- The 13 New York/DAG-BS samples appear only in
  `03_NY-2023-26-10`, consistent with one sequencing round.
- Eight WRG samples appear only in `04_Baalsrud-DNA1-2023-11-23`.
- Thirteen Fennoscandian/WRG `X42`-`X54` samples appear only in
  `02_Boessenkool-DNA5-2022-05-31`.
- Thirty-three `merged_X` samples have matching trimmed FASTQ pairs in both
  `01_boessenkool-DNA4-2022-01-19` and
  `05_Boessenkool-DNA4-2023-11-23`, supporting that these were resequenced and
  later merged for analysis.
- `FNM12`/`X5` currently has only the round 01 trimmed FASTQ pair in this list;
  this is consistent with samples not being resequenced when one round already
  provided sufficient coverage.
- Five FASTQ codes in the listing do not match the curated Snowy Owl table:
  `X38`, `X39`, `X40`, `X41`, and `Undetermined`. These correspond to outgroup
  or undetermined-read files rather than curated Snowy Owl population samples.

## Current limitations

- Raw, untrimmed FASTQ filenames are not present in the recovered project files,
  so final ENA raw-read filenames must be filled from the storage location used
  for ENA upload.
- Samples with `merged_` analysis IDs likely represent merged sequencing data;
  confirm all constituent FASTQ/lane files before submission.
- Lane-level statistics were recovered for the DAG-BS/New York batch, but not
  for most older NSC samples.
- Three historical alignment-QC rows exist but are blank in the old supplement:
  `merged_X1`, `merged_X2`, and `merged_X3`.
